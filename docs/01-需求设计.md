# 炸金花游戏需求设计 V1.0

本文是待确认的产品基线，所列数值和地方玩法是建议默认值，不代表唯一的炸金花规则。当前仅完成设计，不包含已实现功能。

## 1. 产品定位与范围

面向熟人娱乐的纸牌游戏：可离线与机器人练习，可注册登录后创建房间或加入房间与朋友对局；管理员管理成员、分配虚拟资产并查询流水。

- 首发形态：响应式网页，适配电脑与手机横屏；支持安装为 PWA。首次加载并完成缓存后可离线单机，首次离线访问无法使用。
- 单机无需登录，采用独立练习币；联机必须登录，采用服务端虚拟金币。
- 联机金币来源仅为注册初始发放及管理员分配，对局可在玩家之间转移。没有充值、提现、兑换、赠送、交易或有价值奖品。
- 默认每个新账号获得 10,000 金币；发放策略可配置，修改只影响新账号，不自动补发老账号。
- MVP 不包含观战、公开聊天、排行榜、比赛、俱乐部、匹配大厅、联机机器人和原生移动应用。

## 2. 角色与权限

| 能力 | 游客 | 成员 | 管理员 | 超级管理员 |
|---|---|---|---|---|
| 离线单机 | 是 | 是 | 是 | 是 |
| 联机、查看自己的资产与战绩 | 否 | 是 | 是 | 是 |
| 查询成员、禁用普通成员、发起密码重置 | 否 | 否 | 是 | 是 |
| 向普通成员发放/扣减金币 | 否 | 否 | 授权额度内 | 是 |
| 修改初始金币和房间模板 | 否 | 否 | 否 | 是 |
| 授予管理员、调整额度 | 否 | 否 | 否 | 是 |
| 查询审计记录 | 否 | 本人的资产记录 | 授权范围 | 全部 |

管理员不能调整自己或其他管理员的资产，不能给自己提权。超级管理员的自我调账也必须填写原因并记录审计。所有后台账号均无法查看进行中对局的底牌。首个超级管理员通过部署命令创建，注册接口不能指定角色。

## 3. 用户流程与页面

### 3.1 游客与单机

首页 → 单机练习 → 选择 1～5 名机器人及难度 → 开始对局 → 结算 → 再来一局。

练习币默认 10,000，可随时重置。设置、练习币和未结束单机局保存在本地。清除浏览器数据可能丢失单机进度，不影响联机账号。离线存档不上传、不兑换联机金币。单机支持暂停，联机不支持暂停。

机器人只使用自己的手牌和公开信息；简单难度偏随机，中等难度基于牌力和下注行为，困难难度在可观察信息下抽样估计胜率，禁止读取其他玩家底牌。

### 3.2 注册登录

- 用户名、密码、确认密码、昵称；用户名唯一，昵称不作为账号标识。
- 默认采用邀请码注册，后台可切换开放注册或关闭注册；邀请码限制有效期和使用次数。
- 注册、创建钱包、发放初始金币必须整体成功或整体失败；客户端重试不会重复发放。
- 支持登录、退出、修改密码；MVP 由管理员生成一次性密码重置凭证，使用后要求设置新密码。
- 账号被禁用后不能加入新局；若正在牌局中，由系统在其行动时自动弃牌，已提交下注正常结算，然后清退。
- 同一账号仅允许一个有效联机控制会话；新会话登录后旧会话失去操作权。

### 3.3 联机

登录 → 大厅 → 创建房间/输入房间码 → 配置带入金币 → 入座准备 → 发牌 → 轮流操作 → 结算 → 再次准备。

- 2～6 人开局，默认 6 个座位；只要至少 2 名入座玩家且所有入座玩家均准备，即开始 3 秒倒计时。
- 倒计时中取消准备或离开会取消倒计时；发牌前再次验证人数、余额和状态。
- 房间码只作为定位标识，可额外设置房间密码；尝试加入须限速。
- 进行中不允许新玩家入座，返回“牌局进行中”；已有玩家重连不受影响。
- 房主只负责创建和开局前设置，不具备判胜、改币和看牌权限。房主离开后按入座时间移交。
- 玩家在等待阶段可退出并退回桌上余额；进行中点击退出视为弃牌，结算后自动离桌。
- 默认断线保留座位 60 秒，行动时限仍继续；超时自动弃牌，不能利用断线延长思考时间。
- 断线期间本局结束则正常结算；重连宽限结束后清退，当前局未结束时挂起离桌直到结算。
- 房间无人时关闭；空闲 30 分钟关闭房间并退还桌上余额。进行中不因空闲计时器直接销毁。

### 3.4 页面清单

| 页面 | 主要内容 |
|---|---|
| 首页 | 单机入口、联机入口、玩法说明、离线状态 |
| 登录/注册 | 表单、邀请码、错误提示 |
| 大厅 | 余额、创建房间、房间码加入、个人入口 |
| 房间准备 | 座位、规则、带入金币、准备状态 |
| 牌桌 | 底牌/牌背、底池、各人投入、当前行动者、倒计时、合法操作 |
| 结算 | 获胜者、各人净变化、自己手牌、规则版本、再来一局 |
| 个人中心 | 昵称、密码、余额、流水、历史对局 |
| 管理后台 | 成员、资产操作、流水、房间、配置、审计 |

牌桌将“当前需支付金币”和“操作后剩余金币”明确显示。客户端只能展示服务端给出的合法操作；网络等待时锁定重复点击，服务器仍独立校验。使用花色形状、文字和颜色共同区分牌，不只依赖颜色。

## 4. 默认玩法：classic-v1

### 4.1 手牌与大小

- 使用标准 52 张牌，无大小王，每人 3 张；花色不参与大小比较。
- 牌型：豹子 > 顺金 > 金花 > 顺子 > 对子 > 单张。
- A 最大；顺子 AKQ 最大，A23 最小，QKA 合法，KA2 不合法。
- 默认关闭“235 大于豹子”；MVP 不提供此开关，避免非传递大小关系影响多方摊牌。
- 豹子比三张点数；顺金和顺子比顺子序号；金花和单张按降序逐张比；对子先比对子点数，再比单牌。
- 比牌两人完全同点数时发起者输；最终多人强制摊牌如有并列最大则平分底池，余数按从庄家下一席起的顺时针顺序分配给并列赢家。

### 4.2 庄家、轮次与动作

- 首局庄家随机，后续每局顺时针移至下一个有资格开局的座位；首个行动者为庄家下一席。
- 开局每人支付相同底注，再发牌；看牌不会补收底注。
- 默认底注 10，当前基础注额 q 初始为 10；可用基础注额为底注的 1、2、5、10 倍，最大 100。
- 闷牌跟注支付 q；已看牌跟注支付 2q。这里是每次行动新投入金额，不是补齐历史累计投入。
- 加注将 q 提升到更高合法档位，并按新 q 支付闷牌或看牌金额，不能降低 q。
- 仅当前行动者可看牌；看牌不结束本次行动，不重置倒计时，看过后不可恢复闷牌。
- 可选择弃牌、跟注、加注；从第 2 轮起可选择任意仍在局中的其他玩家比牌。
- 比牌费用为发起者当前跟注费用的 2 倍，全部进入底池；目标不付额外费用。无需双方看牌，也不强制改变看牌状态。
- 比牌后败者出局，胜者继续；只返回胜负，不揭示双方底牌。发起比牌消耗一次行动，然后轮到发起者之后的下一名存活玩家。
- 每轮开始生成尚存玩家的行动队列；每人获得一次行动机会，队列内已出局者跳过；队列耗尽视为一轮结束。看牌不算独立行动。
- 只剩 1 人立即获胜。完成第 20 轮且仍有多人，服务器强制比较所有存活手牌并结算。
- 每次行动默认 20 秒，超时弃牌。弃牌和比牌失败都不退回已投入金币。
- 默认不公开其他玩家底牌，包括弃牌者和最终赢家；个人历史只显示自己的牌。后续可增加玩家自愿亮牌。

### 4.3 带入和余额不足

联机采用钱包与桌上金币分离：入座将选择金额从钱包转到桌上账户，离桌将剩余金额转回。

- 默认带入 2,000，最低为底注的 20 倍，最高 10,000；实际不能超过可用钱包余额。
- 每局准备时要求桌上余额至少为底注的 20 倍；局间可从钱包补充，局内不允许补充。
- MVP 没有全押、借款和边池。余额不足的动作不可执行；若仍够较低成本的合法动作则保留，否则只能弃牌。
- 不允许负余额；禁止将钱包金额直接用作局内下注。
- 玩家体验提示：“本版本不支持全押，建议开局前补足桌上金币。”

### 4.4 可配置边界

MVP 允许管理员配置房间模板中的人数、底注、注额档位、最大轮数、行动时间、带入范围；模板要通过范围和相互约束校验。房主只选择模板，不任意拼装规则。每局开始时保存完整规则快照与版本，新配置不影响已开始对局。

## 5. 虚拟资产与后台

### 5.1 资产规则

- 所有金币使用整数，显示“虚拟金币”，禁止小数和浮点计算。
- 每次资产变更必须有唯一业务编号、类型、时间、前后余额、金额和来源。
- 类型包括初始发放、管理员发放、管理员扣减、带入、离桌退回、下注、结算、异常撤销。
- 管理员只能扣减钱包可用余额，不得扣减桌上余额或底池；不足则整笔失败。
- 管理员调账必须填写原因；提交前展示账号、当前余额、变更金额与预计余额。
- 批量发放后续实现；MVP 先做单用户调账，管理员单笔/每日额度由超级管理员配置。
- 账本禁止编辑删除，误操作用关联原流水的新反向操作纠正；玩家已经花掉的金币不能通过强制反向操作制造负余额。
- 无抽水。正常牌局中所有桌上余额与底池总和保持不变。

### 5.2 后台功能

成员搜索与筛选、账号状态、注册时间、钱包余额、当前房间；禁用/启用、密码重置；资产发放与扣减；按账号/时间/业务类型查询流水；对局和异常局查询；管理员操作审计；注册方式和初始资产配置。

后台房间管理提供“本局结束后关闭”和“异常中止”。正常关闭等待本局结算；异常中止整局退回各人本局投入并记录原因，不能随意指定赢家。敏感操作需要近期重新验证身份，管理员强制启用 MFA。

## 6. 异常处理

| 情况 | 预期行为 |
|---|---|
| 重复点击或请求重试 | 同一请求只执行一次，返回第一次结果 |
| 旧页面/乱序请求 | 拒绝过期版本，并下发最新可见状态 |
| 支付成功但响应丢失 | 重连或重试获取已成功结果，不重复扣款 |
| 离线或服务器不可达 | 提示联机不可用，仍可进入已缓存单机 |
| 服务端重启 | 已结算局保持结算；MVP 未完成局整体撤销并退还本局投入 |
| 数据库不可用 | 停止接收游戏和资产变更，不凭内存宣布操作成功 |
| 存档规则版本不兼容 | 提示重开单机局，保留可迁移设置 |
| 游戏中维护 | 停止新局，等待在局结算；超出维护期限则执行可审计撤销 |

## 7. 分期与验收

### MVP 必须完成

1. 统一规则引擎、完整牌型比较、单机机器人和本地存档。
2. 注册登录、初始资产、个人流水。
3. 房间、准备、完整联机回合、断线重连、结算。
4. 后台成员管理、资产调账、权限与审计。
5. 幂等、崩溃撤销、资产核对、部署备份与恢复演练。

### 后续增强

可选玩法、好友、邀请链接、表情、历史动画回放、批量资产发放、排行榜、观战和联机机器人。每项都另行评审隐私、规则及资产影响。

### 关键验收用例

- 不登录、断网且资源已缓存时，能完成一局单机；本地修改练习币不能影响联机账户。
- 注册并发重试也只收到一次初始金币，邀请码次数不超发。
- 2～6 个浏览器可完成整局，下注、轮次、赢家和各人净变化一致。
- A23、AKQ、对子、完全相同点数等边界符合 classic-v1；235 不作为特殊牌型。
- 闷牌/看牌费用、比牌平局、强制摊牌平分和余数分配均正确。
- 越权操作、非本人回合、余额不足、过期状态不改变牌局或资产。
- 管理员重复提交、同时扣款、超额扣款不会重复记账或使余额变负。
- 浏览器网络消息中不出现其他玩家底牌；自己未看牌前也收不到自己的牌值。
- 在下注提交、结算提交前后模拟崩溃，恢复后每局只有“结算”或“撤销”一种结果且资产守恒。
- 冻结成员、断线超时、房主离开、同账号换设备不会卡住牌局。
